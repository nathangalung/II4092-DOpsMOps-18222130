## Unifying root cause (corrected — see Corrections log)

The one genuinely-down family is **false-positive liveness-probe SIGKILLs on IO-sensitive
control-plane pods**. Single-node k3s runs kine on SQLite; chronic IO pressure (worsened by a
backlog of un-GC'd Failed pods inflating kine object count → slower list/watch) intermittently
stalls health endpoints or briefly drops their listeners (`connection refused` = instant TCP
RST). Over-aggressive liveness probes then trip kubelet SIGKILL → restart loops → the cascade
below. The fix is to widen the probe tolerance windows, NOT to disable the features the earlier
triage blamed (leader election, SSE-KMS).
